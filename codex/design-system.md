# Sistema visual y experiencia

LIARD Lab usa una estética de taller editorial: verde profundo para el espacio de trabajo, lima eléctrica para acciones primarias, superficies claras para evidencia, azul para información y ámbar para decisiones pendientes. El acento enfatiza una siguiente acción, no todos los estados.

Tokens en tokens.css; componentes en ui.css. Tipografía sistema offline, mono para cantidades/atributos, títulos compactos 28–42 px, cuerpo 14 px y tablas 13 px. Grilla flexible 20/22 px; tarjeta 24 px; radios 10/18 px. Evitamos recursos externos para que el demo funcione sin conectividad. Íconos SVG inline propios consistentes; no emojis en controles.

El contexto de proyecto/rol y variantes vive en la cabecera. La navegación representa decisiones del expediente, desde ingeniería hasta activo. Las acciones de alto impacto muestran revisión, condiciones y resultado persistido; las simulaciones tienen etiqueta explícita. Cada pantalla conserva el camino anterior/siguiente; las páginas y exportaciones usan el mismo store.

La variante guiada reduce decisiones simultáneas; experta pone los datos editables juntos; asistida acompaña fuentes/reglas sin reemplazar el juicio; visual enlaza selección y detalle con una vía tabular. El modelo 3D es propio y conceptual, con selección, rotación, escala y despiece; nunca se deriva automáticamente de un DXF en esta demo.

Accesibilidad: HTML semántico, labels, foco visible, estado anunciado, acceso a contenido, botones con nombre, contraste de texto, alternativa 2D, sin información solo por color. Movimiento breve no esencial; respeta prefers-reduced-motion. El trabajo de obra prioriza móvil y controles grandes. Los frames de galería conservan resolución desktop/phone y ofrecen apertura completa; las pantallas se adaptan fuera de los frames.

Privacidad de producción: contexto privado de empresa, catálogo propio del proveedor y solicitudes destinadas; competencia, margen y documentos de otro usuario no se muestran en el portal del proveedor. El store local compartido es una simulación, no un mecanismo de autorización. Roles/cuenta/cookies de producción no se modificaron.
